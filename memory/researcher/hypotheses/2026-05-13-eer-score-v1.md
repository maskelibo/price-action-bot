# HYP-2026-05-13-001 — EER-Score v1 (Expected Edge Rank Percentile)

## 1. Pre-Registered İddia (TEK CÜMLE)

> Her trade için, **trade entry_ts'inden önceki 180-gün rolling pencerede**,
> aynı `(strategy_id, symbol, regime_bucket, atr_pct_bucket, funding_sign,
> fng_bucket)` kombosuna ait kapanmış trade'lerin **gerçekleşmiş avg_R
> percentile'ı** (n ≥ 30 olduğu zaman; aksi durumda 0.50 medyan fallback)
> hesaplanır. Bu **EER-Score**, ham `confluence_score` ile karşılaştırıldığında
> **3y rolling (3y/6m walk, step 3m, 13 pencere)** üzerinde **tier-bazlı sizing
> overlay'inde OOS Sharpe %20+ daha yüksek bir kazanç sağlar.**

**Bağımlı değişkenler:** OOS Sharpe (windowed), yıllık net return, OOS max
drawdown, Top-tier vs bottom-tier avg_R spread.

(yukarıdaki 6 dim), sample_min eşiği (default 30), tier kesim
percentile'ları (default 20/40/30/10).

**Null hipotezi:**
- EER percentile rank'inin yıllık delta'sı (vs ham conf): 13 pencere ortalaması
  **< +3pp** VEYA

def infer_buckets(trade_entry_ts, symbol, daily_features):
    # All references are to entry_ts - 1 day (yesterday's close).
    yesterday = trade_entry_ts.normalize() - pd.Timedelta(days=1)
    btc = daily_features["BTC/USDT"]   # 1d OHLCV w/ EMA200, ATR%, 90d-DD precomputed
    btc_yest = btc.loc[btc.ts <= yesterday].iloc[-1]
    regime_bucket = (
        "bull"  if btc_yest.close > btc_yest.ema200 and btc_yest.dd_90d > -0.10
        else "bear" if btc_yest.dd_90d <= -0.25
        else "range"
    )
    sym = daily_features[symbol]
    sym_yest = sym.loc[sym.ts <= yesterday].iloc[-1]
    atr_pct_bucket = quintile_lookup(sym_yest.atr_pct,
                                     trailing_252_quantiles[symbol][yesterday])
    funding_yest = funding_series.loc[funding_series.ts <= yesterday].iloc[-1]
    funding_sign = "pos" if funding_yest > 1e-4 else "neg" if funding_yest < -1e-4 else "neutral"
    fng_yest = fng_series.loc[fng_series.ts <= yesterday].iloc[-1].value
    fng_bucket = (
        "ef" if fng_yest < 20 else "f" if fng_yest < 40
        else "n" if fng_yest < 60 else "g" if fng_yest < 80 else "eg"
    )

### 3.3 EER Computation

```
def compute_eer(trade, history_trades, lookback_days=180, sample_min=30):
    """
    history_trades: TÜM (strategy_id, symbol) için kapanmış trade'ler.
    Her birinin exit_ts < trade.entry_ts olmalı (kapanmış olma garantisi).
    """
    # 1. Trade'in bucket key'ini öğren (causal — yukarıdaki infer_buckets)
    key = infer_buckets(trade.entry_ts, trade.symbol, ...)
    cutoff_start = trade.entry_ts - timedelta(days=lookback_days)

    # 2. Aynı bucket key'e ait, exit_ts < entry_ts olan trade'leri filtrele
    matching = [
        h for h in history_trades
        if h.exit_ts < trade.entry_ts                      # KAPANMIS sart
           and h.exit_ts >= cutoff_start                   # son 180 gun
           and bucket_key(h) == key                        # ayni bucket
    ]

    if len(matching) < sample_min:                         # n<30 → fallback
        return 0.50

    bucket_avg_R = mean([h.R for h in matching])

    # 3. Ayni 180-gun penceredeki TUM bucket'larin avg_R distribution'inu cikar
    all_buckets = group_by(history_trades_in_lookback, bucket_key)
    bucket_avgs = [
        mean([h.R for h in trades_in_bucket])
        for trades_in_bucket in all_buckets.values()
        if len(trades_in_bucket) >= sample_min
    ]
    if len(bucket_avgs) < 5:
        return 0.50   # cok az bucket — anlamli percentile yok

    # 4. Percentile rank
    rank = (sum(1 for x in bucket_avgs if x <= bucket_avg_R) / len(bucket_avgs))
    return rank   # [0.0, 1.0]
```

### 3.4 Sample-Size Kuralı — Niye n ≥ 30?

İstatistiksel gerekçe (TÜM SAYI):
- **Central Limit Theorem prakikat eşiği:** Avg-R dağılımı yaklaşık normal kabul
  edilebilir hale gelir n≥30 olduğunda (Hogg & Craig, "Intro to Math Stats", ch.5).
- **Standart hata yarı yarıya:** σ_R / sqrt(30) = σ_R / 5.48. Bizim historic
  trade-level σ_R ≈ 1.5 (single-trade R volatility). n=30 için SE ≈ 0.274. Yani
  bucket avg_R için 95% CI yarı genişlik ≈ 0.54 R. Sample boyutu 10 → CI yarı
  genişlik 0.95 R (anlamlı değil). Sample 30 → kabul edilebilir 0.54 R sinyal/gürültü
  oranı.
- **Curve-fit risk:** n=10 ile bucket avg_R çok değişken; rank assignment trade
  başı %5 düzeyinde "rastgele" eklenir. n=30 ile bu varyans yarıya iner.
- **Fallback değeri 0.50:** Medyan = tier orta noktası = mevcut BALANCED %3 risk
  seviyesi (Lab varsayılanı). Conservatif, sapma yok.

**Limit:** n≥30 sample-size kuralı `sample_min` parametresi olarak modüle expose
edilir. Robustness suite'i 20/30/50 ile karşılaştıracak (Section 6).

### 3.5 Tier Hedefi (sizing'e map)

EER continuous percentile (0-1). Lab'in tier yapısı önerilen 4-bucket:
- **T1 (EER < 0.20):** %1 risk, 1× leverage  (sinyalin %20'si)
- **T2 (0.20 ≤ EER < 0.60):** %2 risk, 2×    (%40 sinyal)
- **T3 (0.60 ≤ EER < 0.90):** %3 risk, 3×    (%30 sinyal)
- **T4 (EER ≥ 0.90):** %4 risk, 3×           (%10 sinyal, NOT 7%)

Sizing tier'ları **bu pre-registration'ın değil**, Lab'in işi. Bu hipotez sadece
**EER metriğinin OOS edge'ini doğrular**; tier kalibresi W3 tournament konusu.

## 4. Walk-Forward Protokolü

### 4.1 Yöntem (3y/6m, step 3m)

- **In-sample:** 3 yıl trade'leri, EER lookup table oluştur (bucket → avg_R hash).
- **Out-of-sample:** Sonraki 6 ay. Bu pencerede EER her trade için **in-sample'dan
  hesaplanır** (look-ahead yok).
- **Slide:** +3 ay, tekrar. 5y data → 13 pencere (CEO Brief'teki standart sayı).

Penceredeki her trade için **iki paralel sizing** uygulanır:
- **Kontrol (CONF):** Mevcut BALANCED — conf_pct percentile bucket'tan tier
- **Tedavi (EER):** EER bucket'tan tier (aynı tier dağılımı 20/40/30/10)

Pencere başına metrikler:
- OOS Sharpe (CONF vs EER)
- OOS yıllık return (CONF vs EER)
- OOS MaxDD (CONF vs EER)
- Top-tier avg_R (CONF vs EER) — Welch t-test, p<0.05 gate

### 4.2 Çoklu Test Düzeltmesi

Bonferroni korreksiyonu:
- Test edilen feature kombinasyonu: 1 (sabit 6-dim bucket key — sweep YASAK)
- Test edilen sample_min eşiği: 1 (sweep YASAK pre-reg)
- Test edilen lookback_days: 1 (sweep YASAK pre-reg)
- Pencere sayısı: 13
- Bonferroni α: 0.05 / 13 = **0.00385**

Yani her pencerede shuffle null'a karşı p<0.00385 lazım. Veya pencere
ortalaması için single-test p<0.05 ile yetinilir + bootstrap CI ile dağılım
gösterilir.

### 4.3 Shuffle Null Baseline

**Procedure:** Her pencerede EER hesaplandıktan sonra trade'lerin EER
etiketlerini **random shuffle** et (in-window, exit_ts'leri sabit). Bu null
modelde EER permüte edilmiş — gerçek bucket-edge ilişkisi yok ama sample
distribution'u aynı.

- 200 shuffle iteration
- Her shuffle için: EER tier sizing → Sharpe
- Real EER Sharpe'i shuffle dağılımının üst kuyruğuna (p<0.05) düşmeli

**Gate:** 13/13 pencerede shuffle p<0.05 gerekmez (pratik değil); **ortalama
pencere shuffle p<0.05** + **13 pencereden 10+ shuffle p<0.05** yeterli.

### 4.4 Bootstrap CI

- 2000 bootstrap iteration: pencere içi trade'leri replacement-with sample
- Her bootstrap'ta: EER_Sharpe - CONF_Sharpe delta
- 95% CI alt sınır > 0 olmalı (null'a karşı)

## 8. Karşı-Hipotez (önemli)

**Karşı-hipotez 1: Bucket clustering bias.**  6-dim bucket key kombinatorik
patlama (10 strateji × 11 sembol × 3 regime × 3 atr × 3 funding × 5 fng =
14850 olası bucket). Pratikte trade dağılımının %80'i 50-100 bucket'ta yığılır;
geri kalan 14000+ bucket boş veya n<30. Bu **fallback yığılması** demektir
(0.50 medyan). Eğer fallback oranı **>%70** ise EER pratikte conf'la özdeş
davranır → RED.

**Karşı-hipotez 2: 180-gün lookback yetersiz.**  Crypto rejim shift'leri
hızlı (3-6 ay). 180-gün lookback bull-only veya bear-only veriyle dolarsa
EER bucket'ı **regime-bound** olur — yeni regime'e geçince yanlış sinyal. Bu
risk regime_bucket feature'la **kısmen azaltılır** ama bull regime trade'i
azsa hala overfit riski var. Symbol-out CV bunu yakalamalı.

**Karşı-hipotez 3: Top-tier avg_R düşük → tier sizing değersiz.**  Eğer
top-tier (EER ≥ 0.90) avg_R **bottom-tier'dan istatistiksel anlamlı yüksek değil**,
EER tier'a map edilse bile sizing edge yaratmaz. Bu Top-tier vs Bottom-tier
Welch t-test gate'inin (p<0.05) raison d'être'i.

**Karşı-hipotez 4: Conf zaten bozuk, EER de düzgün değil — sadece DAHA AZ
bozuk.**  Eğer EER OOS Sharpe uplift'i +0.05-0.15 ise (eşik %20 değil), hipotez
RED ama "yön doğru" notu. Sonraki sprint'te EER v2 (ek feature, daha derin
bucket) düşünülür.
